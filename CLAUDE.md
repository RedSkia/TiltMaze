# TiltMaze (AI-noter)

Labyrintspil, .NET MAUI Blazor Hybrid (Android + Windows) + ASP.NET Core API (Docker). Kode HELT simpelt, skrevet som et menneske (skoleprojekt, Marcus skal kunne forklare hver linje). Dansk i docs og kommentarer, engelsk i UI. Plan: `docs/plan.md`. Design og lag: `DESIGN.md`.

## Tree
- `TiltMaze.Core/` ren C# (net10.0), ingen MAUI: `Maze.cs` (Wall, Cell, MazeGenerator: DFS + rum + braiding + Distances), `Difficulty.cs` (Easy/Normal/Hard/Expert og deres indstillinger), `Course.cs` (labyrint fra sværhedsgrad + seed: start i hjørne, mål langt væk, små og store huller, mønter, vægge som linjestykker, `Check` for træk mod hul, hul og mål, `TouchesCoin`), `Rewards.cs` (mønter pr. belønning, top-listebonus, kuglens farver og priser), `Ball.cs` (fysik, fast tidsskridt 1/120 s, kollision cirkel mod linje), `Camera.cs` (udsnit der glider efter kuglen, holdes inden for banen), `Ghost.cs` (afspil optaget løb, første besøg pr. celle til mellemtider, til/fra bytes), `Format.cs` (tid og +/- forskel), `ShopItems.cs` (butikkens ting: `ShopCategory`, `ShopItem`, katalog, `OwnedKey`, farver til spor), `Trail.cs` (ringbuffer med kuglens sidste 14 positioner), `Nickname.cs` (brugernavnets regel, bruges af app og API)
- `TiltMaze.App/` MAUI Blazor Hybrid, Android (min API 26) + Windows (`WindowsPackageType None`), id `com.redskia.tiltmaze`
  - `Components/ConfirmDialog` fælles in-app dialog (sikker knap først med fokus, `Esc` = sikker knap): bruges af "Delete account?" i Account
  - `Components/Layout` MainLayout (læser login og låser op med fingeraftryk ved start, før siderne vises) + NavMenu (Play, Leaderboard, Shop, Account, About; bundmenu på telefon, sidemenu fra 768 px)
  - `Components/Pages` Start (`/`, "Play daily"-kort med dato, egen tid og nedtælling til næste daglige + sværhedskort i farver: 1 kolonne/2x2/række), Game (`/play/{DifficultyName}/{Seed:int?}`), Leaderboard (`/leaderboard`, podie for top 3, valg til venstre og liste til højre fra 900 px), Shop (`/shop`: saldo, 5 faner, kort med forhåndsvisning), Account (`/account`, profil med avatar, indstillingsrækker, farezone; to kolonner fra 900 px), Login (`/login`), About (kort: om, sådan spiller man, privatliv, RedSkia.Dev), NotFound. Hver side: `.razor` + `.razor.cs` + `.razor.css` (NotFound kun `.razor`)
  - `Components/Play` dele af spilskærmen: `MazeLayer` (fast bane: gulv, huller, mål, vægge; tegnes kun ved ny labyrint, `Mini` = minikort), `BallPattern` (mønster oven på kuglen, kun SVG), `TrailView` (spor bag kuglen), `BallPreview` (kugle i Shop), `Joystick` (flydende: felt over hele banen, ringen kommer frem hvor første finger trykker, pointer capture, X/Y fra -1 til 1), `RivalGhost` (en andens spøgelse: kugle + brugernavn)
  - `Services/` `Scores` (bedste tid + spøgelse pr. sværhedsgrad+seed), `Wallet` (mønter, ejede ting, valgt ting pr. slags i Preferences `ballColor`, `trail`, `pattern`, `goalEffect`, `theme`), `Sound` (kalder lydene i game.js, Preferences `sound`, standard til), `GameDatabase` (SQLite: BestRun, PendingRun, MazeProgress, WalletRow), `Auth` (login med brugernavn, tokens i SecureStorage, låst/låst op), `Biometrics` (fingeraftryk/Windows Hello, `Oscore.Maui.Biometric`, Preferences `biometricLogin` og `biometricAsked`), `Api` (HTTP), `RunQueue` (sender ventende rekorder), `ApiSettings` (adresse), `TiltSensor` (accelerometer til vip)
  - `wwwroot/app.css` design-tokens "Neon Arcade" og fælles klasser (også dialogerne), `wwwroot/js/game.js` (ResizeObserver til banens størrelse, pointer capture til joysticken, `tiltMaze.sound`: lyde syntetiseret med Web Audio, ingen lydfiler), `wwwroot/images/` logo + RedSkia-logo
  - `Platforms/` Android- og Windows-indgang
- `TiltMaze.Tests/` xUnit: alle sværhedsgrader x mange seeds (mål nås uden store huller, start/mål aldrig huller, samme seed = samme labyrint, små huller har en åbning), fald/hop over huller, træk mod hullet, kuglen går ikke gennem vægge, kamera, spøgelse, tidstekster, brugernavn, mønter (samme seed = samme mønter, aldrig på start/mål/huller, antal pr. sværhedsgrad, berøring) og belønninger (`Rewards`)
- `TiltMaze.Api/` ASP.NET Core minimal API (net10.0, refererer Core): `Program.cs` (opsætning + alle endpoints), `GameDb.cs` (EF Core SQLite: Identity's `IdentityUser`, `Runs`, DTO'er), `RunChecker.cs` (anti-snyd), `IdentityErrors.cs` (engelske fejltekster), `Dockerfile`
- `TiltMaze.Api.Tests/` xUnit + `WebApplicationFactory` (midlertidig SQLite): konto og login (unikt navn, ledigt-tjek, lås efter 5 forkerte, samme 401), endpoints, rate limits, sikkerhed (ingen CORS, ingen detaljer i fejl, nøgler gemmes), anti-snyd (teleport, gennem væg, for hurtig, forkert mål/tid, uens billedtider, for langt spøgelse). `Player.cs` er en computer-spiller, der laver rigtige ture på alle sværhedsgrader (uden om store huller, forbi små; `avoidHoles: false` kører lige igennem og hopper)
- `compose.yaml` (API i Docker), `.env` (kun `CERT_PASSWORD`, aldrig i git; skabelon `.env.example`)

## API
- Adresse `https://localhost:7065` (Docker 7065→8443, cert `tiltmaze.pfx` fra `CERT_DIR`, standard `%USERPROFILE%/.aspnet/https`). Volumen `tiltmaze-data` har databasen og `keys` (DataProtection). Android når den via `adb reverse tcp:7065` (sættes ved Debug-build, sammen med `docker compose up -d --build`).
- Konti: brugernavn + kodeord, ingen e-mail. Brugernavnet (`IdentityUser.UserName`) er også navnet på top-listen: 3-16 tegn `[A-Za-z0-9_]` (`Nickname` i Core), unikt uden forskel på store/små (Identity's unikke indeks på `NormalizedUserName`).
- Login (Identity bearer-tokens, egne endpoints, ingen `MapIdentityApi`): `POST /api/auth/login {username,password}` → `{accessToken, expiresIn, refreshToken}` (SignInManager med `IdentityConstants.BearerScheme`), `POST /api/auth/refresh {refreshToken}`. Fejl: altid 401 "Wrong username or password" (også ukendt navn og låst konto).
- Konto: `POST /api/account {username,password}` (409 "That username is taken"), `GET /api/account/available?username=` → `{available}` (åben, 30/min pr. IP; appen spørger 400 ms efter sidste tast), `GET /api/account` → `{username}`, `PUT /api/account/username` (409 hvis taget; tokens gælder stadig), `DELETE /api/account` (sletter også tider og spøgelser).
- `POST /api/runs {difficulty, seed, timeMs, ghost(base64 float32 LE)}` (login, 20/min): `RunChecker` bygger `Course(difficulty, seed)` og tjekker spøgelset (start, mål, skridt ≤ maks-fart, aldrig i væg, fald = hop til start, tid = antal målinger ±1). Max længde `RunChecker.MaxSamples`, og `MaxGhostBytes` i `Program.cs` afledes af den. Fejl: 400 "Run could not be verified". Kun brugerens bedste tid pr. labyrint gemmes. Svar: `{id, timeMs, isBest, rank}`, hvor `rank` er pladsen for brugerens bedste tid (appen giver top-listebonus ud fra den).
- `GET /api/leaderboard/{difficulty}/{seed}?top=10` (åben; `isMe` hvis logget ind) → `[{rank, runId, username, timeMs, isMe}]`. `GET /api/runs/{id}/ghost` (login; kun top 10 og egne) → `{username, timeMs, ghost}`. `GET /api/daily` → `{seed}`.
- Fejl er altid ProblemDetails med engelsk `title`. Rate limits: `runs` 20/min og `read` 60/min pr. bruger/IP, `auth` (login, refresh, opret) 20/min pr. IP (`RateLimits:Auth` i konfigurationen, kun ændret i en test), `available` 30/min pr. IP.
- Sikkerhed (server): kodeord som hash, mindst 8 tegn; 5 forkerte kodeord = låst i 5 min; login-fejl er ens (ingen afsløring af navne, ud over ledigt-tjekket med rate limit); alt med tider og konto kræver login undtagen `GET` top-liste og dagens seed; spøgelse højst `MaxGhostBytes`/`MaxSamples`, sværhedsgrad og seed tjekkes; ingen stacktrace eller detaljer i fejl; kun HTTPS (HSTS uden for Development); CORS er ikke slået til; DataProtection-nøgler i volumen. App: refresh-token kun i SecureStorage, adgangstoken kun i hukommelsen; fingeraftryk låser kun det gemte login op på enheden og sender aldrig biometri nogen steder.
- Appen: tider ligger i SQLite (`GameDatabase`); `Scores.Save` gemmer tid + spøgelse og lægger rekorden i `PendingRun` (med `Username`: brugeren der satte den, tom = gæst) i én transaktion. `RunQueue` sender kun gæsterekorder og den indloggede brugers egne (ved udløbet login bevares rekorderne, men sendes ikke under en anden bruger); den sender ved start, efter login, ved ny rekord og når nettet kommer tilbage. `Api.GetTopGhosts(difficulty, seed)` giver top 3 andres spøgelser (egen tur springes over); Game henter dem i baggrunden ved start, når man er logget ind og online. Tokens i `SecureStorage`: `refreshToken`, `refreshExpires`, `username`. Fingeraftryk slået til (Account, eller ja til spørgsmålet efter første login): appen starter låst (`Auth.IsLocked`), `MainLayout` beder om fingeraftryk; annulleres det, spiller man som gæst og kan låse op eller skrive kodeordet på Account.

## Regler
- Al matematik (labyrint, fysik) i `TiltMaze.Core` og testet. Siderne tegner og styrer kun.
- Ingen baner/levels: hver labyrint er `(Difficulty, seed)`. Dagens labyrint har datoen (UTC, `yyyyMMdd`) som seed. Tilfældig seed: `Course.NewSeed()`.
- Enheder: 1 celle = 1 enhed, y går nedad. Start i et hjørne, mål blandt de fjerneste celler (bredde-først afstand).
- Huller: små (radius 0,13-0,175, kuglen kan rulle forbi langs siden) og store (`Hole.BigRadius` 0,46, fylder gangen; kun på korteste vej og kun hvis målet nås uden alle store huller). Halvdelen af de små ligger på vejen uden om de store. Inden for hullets radius + `Course.PullMargin` trækkes kuglen mod midten (`PullAccel` 3, svagere end vip). Kuglen falder, når dens midte er inde i hullet og farten er under `Course.JumpSpeed` (75 % af maks), eller den er over hullet længere end `MaxTimeOverHole` (0,19 s). Træk, hul og mål tjekkes efter hvert fysik-skridt (`Course.Check`, callback til `Ball.Update`); trækket ændrer kun farten, som `Ball` klipper til maks-farten, så `RunChecker` passer uden ændring (`MaxSamplesInHole` afledes af `MaxTimeOverHole`).
- Tid og spøgelse følger fysikken: `Game.CheckOutcome` kører efter hvert fysik-skridt, tæller `steps`, sætter `time = steps * Ball.Step` og gemmer kuglens x,y som `float[]`, hver gang tiden passerer et nyt 1/30 s (`Ghost.Rate`). Billedernes længde påvirker altså ikke optagelsen. Spøgelset gemmes i SQLite (`BestRun.Ghost`) ved ny rekord og sendes til serveren som base64 af float32 (`Ghost.ToBytes` i Core). Serveren afspiller og tjekker det. `Player.cs` i API-testene gør det samme.
- Spil-løkke: `PeriodicTimer` 16 ms i `Game.razor.cs`, `InvokeAsync(StateHasChanged)`. Kun kugle, spøgelser, kamera (`viewBox`), HUD og minikortets prik ændres pr. billede. Den faste bane ligger i `MazeLayer`, hvis `ShouldRender` kun er true ved en ny `Course`. Alle vægge er ét SVG-`path` (i `defs`), tegnet fire gange med `use` (skygge, side, top, glans). Ingen SVG-filtre (blur) på banen.
- Mønter: `Course.Coins` (3/5/7/9 pr. sværhedsgrad, midt i celler uden start, mål og huller, først celler uden for korteste vej; trækkes med samme `Random` efter hullerne, så huller og vægge er uændrede). `Course.TouchesCoin(ball, i)` (radius `CoinRadius` 0,12 + kuglen). Mønter påvirker hverken fysik, tid, spøgelse eller `RunChecker`. Game tjekker efter hvert fysik-skridt (i `CheckOutcome`), giver en lille ring + 15 ms vibration og viser mønter i dette løb i HUD'en.
- Pung (`Wallet`, lokalt i SQLite): hver mønt giver 1 én gang pr. labyrint (`MazeProgress.CoinMask`), at klare labyrinten giver 5/10/20/40 første gang (`Rewards.Completion`), top-listebonus top 10 = 25 og top 3 = 50 én gang pr. labyrint, en højere erstatter en lavere (`Rewards.RankBonusToPay`, `MazeProgress.RankBonusPaid`). `RunQueue` giver bonussen, når serveren svarer med `rank`. Alle tal og priser står i `Rewards.cs`.
- Butik (`/shop`): fem slags i `ShopItems.All` (katalog i Core; første ting i hver slags er gratis og standard, resten koster 30-250). Kun udseende: påvirker aldrig fysik, tid, spøgelse eller `RunChecker`. Faner: Colours (8 farver, `Rewards.BallColors`), Trails (none, Neon, Fire, Rainbow, Sparkle), Patterns (plain, Stripes, Planet, Eye, Neon ring), Finish (Confetti, Stars, Fireworks, Coin rain), Themes (Neon, Lava, Ice, Retro). Kort i CSS-grid (`align-items: stretch`, 2/3/4 kolonner), knapper Buy / Equip / Equipped, "Not enough coins" når saldoen er for lille.
- Ejede ting ligger i `WalletRow.Owned` (komma-liste): farver som bare id (som før, så gamle køb virker), resten som `slags:id` (fx `trail:fire`, `ShopItems.OwnedKey`). Valgt ting pr. slags i Preferences: `ballColor`, `trail`, `pattern`, `goalEffect`, `theme` (ukendt id = den gratis).
- Butik i Game: farven giver kuglens farveforløb og minikortets prik. Sporet er en `Trail` (ringbuffer, 14 positioner, tilføjes efter hvert billede, ryddes ved fald) tegnet af `TrailView` bag kuglen. `BallPattern` ligger oven på kuglen. Temaet er en klasse `theme-<id>` på `.board-area` og sætter `--m-...` (gulv, fliser, vægge, huller; defineret i `app.css`), så `MazeLayer` kun tegnes ved ny labyrint og ikke har faste farver. Effekten ved mål er `.effect.<id>` med 28 `<i>` (42 gnister til fyrværkeri) i CSS-animation og slås fra ved `prefers-reduced-motion`.
- Spøgelser i banen: eget bedste løb (stiplet turkis) og op til 3 andres (`RivalGhost`, hver sin dæmpede farve og brugernavn). Forskellen ("ghost") i HUD'en er kun mod eget løb.
- Kamera: følger kuglen, når hele banen ikke kan vises med mindst 40 px pr. celle (`MinCell`); så vises 56 px pr. celle (`CameraCell`) og et minikort. Banens størrelse kommer fra `tiltMaze.watchSize` (ResizeObserver) → `[JSInvokable] BoardResized`.
- Styring lægges sammen og klippes til -1..1: taster + vip + joystick. Joysticken er altid med: tryk og træk hvor som helst på banen (kun første finger tæller; slip eller pause = 0). HUD-knapperne ligger uden for feltet. Valgt sværhedsgrad på startsiden: Preferences `difficulty`.
- Løbet: nedtælling 3-2-1-Go (`Beat` 0,7 s), fald = rystelse + rødt blink + vibration, mål = konfetti + dialog. Pausemenuen er den eneste menu: Esc, P og HUD-knapperne åbner den samme dialog "Paused" med Resume (fokus, Esc = Resume), Retry og Leave (ingen ekstra spørgsmål). Vinduet skjult pauser også. Dialoger: fokus på første knap, `Esc` lukker, resten af skærmen er `inert`.
- Tal i SVG formateres med `CultureInfo.InvariantCulture` (`N()` i Game, MazeLayer, Joystick og RivalGhost).
- Alle tekster brugeren ser er på engelsk.
- Lyd: korte arkadelyde laves med Web Audio i `tiltMaze.sound` (`game.js`), kaldt via `Sound` (mønt, fald, nedtælling, Go, mål, ny rekord, `Buy` til Shop). Kun hvis Preferences `sound` er til (kontakt i pausemenuen og på Account). Ingen lyd ved vægkollision (Ball afslører den ikke).
- Design "Neon Arcade": natblå baggrund, turkis accent (`--accent`), orange kugle (`--ball`), guld mål/rekord (`--gold`), koral fare (`--danger`). Kun systemskrifttyper. Arkade-knapper med kant (`box-shadow`), der trykkes ned. Alle animationer slås fra eller dæmpes ved `prefers-reduced-motion`.
- Fælles UI og tokens kommer fra `wwwroot/app.css`; sidens egen stil ligger i `.razor.css`. Fælles klasser: `.cta` (kort med tekst + knap, fx "Sign in"), `.icon-button` (rund ikonknap, min 44 px), `.empty-state` (ikon, overskrift, tekst, knap: ingen tider, offline, NotFound), `.hint`, `.password-row`, `.segmented`.
- Layout uden overlap (390, 900 og 1400 px): rækker af knapper bruger `flex-wrap` eller `minmax(0, 1fr)`, `.button` har `max-width: 100%`, `.page-head` brydes, lange navne får "...".
- Mærke: kun RedSkia.Dev (About-kortet med RedSkia-rød `#ee3b33`, "by RedSkia.Dev" på startsiden). Intet personnavn i appen.
- Android-tilladelser: `INTERNET`, `ACCESS_NETWORK_STATE` (appen ser, om der er net, før køen sendes), `VIBRATE` og `USE_BIOMETRIC`.
- Indrykning: 4 mellemrum overalt (ingen tabulatorer).

## Kommandoer
- Build: `dotnet build TiltMaze.App -c Release -f net10.0-windows10.0.19041.0` / `-f net10.0-android`
- Kør: `dotnet run --project TiltMaze.App -f net10.0-windows10.0.19041.0`, telefon: `dotnet build TiltMaze.App -t:Run -f net10.0-android`
- Test: `dotnet test` (Core og API). API lokalt: `docker compose up -d --build` (kræver `.env` med `CERT_PASSWORD`)
